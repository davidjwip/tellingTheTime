# specs/v1.md — clock game, version 1

**Status: DRAFT — awaiting approval.** Per `AGENTS.md`, a spec is approved only when Dave says so
in the project thread. No implementation code until then.

Scope of this spec: **tiers T0–T4** (20 levels). T5–T6 and T7 are out of scope but the data model
accommodates them without change.

---

## 1. Purpose

A supervised web page that helps a four-year-old learn to read an analogue clock, in the same
shape as the existing maths and spelling pages: one large clock, one question spoken aloud, an
adult who marks the answer.

Grounded in `research/` — the teaching order in `02-progression-ladder.md`, the tiering in
`04-game-design-brief.md`.

**Success for v1** is not "he can read a clock". It is: he asks to play it, he can operate it at
T0–T2 without help beyond the marking, and the adult can see which level he is on.

## 2. Non-goals

- No accounts, no backend, no network calls at runtime, no analytics.
- No elapsed-time, 24-hour or Roman-numeral work (that is T7).
- No timers, lives, coins, leaderboards, or daily-streak mechanics.
- No assessment output, report card, or progress email. The adult can see the level and the badges;
  that is the whole reporting surface.
- No reading required of the child anywhere in the UI.

## 3. Users

**Two people, one screen.** The child answers; the adult operates every control, presses every
verdict, and chooses when to stop. The app must never assume the child can read, type, or navigate.

## 4. Content model

### 4.1 Level schema

One declarative file, `src/levels.json`, drives everything. No level behaviour lives in the view.

```ts
type Task = 'order' | 'choose' | 'read' | 'set' | 'build' | 'tap';

interface RoundStep { task: Task; items: number; }   // ordered: reading comes first

interface Level {
  id: string;                  // 't3.2' — stable; used in tests, storage and badges
  tier: 0 | 1 | 2 | 3 | 4 | 5 | 6;
  title: { en: string; yue?: string };      // adult-facing only
  round: RoundStep[];          // sums to itemsPerRound
  minutes: number[];           // allowed minute values, e.g. [0] or [0, 30]
  hours?: number[];            // optional subset, e.g. [12, 3, 6, 9]
  face: {
    hands: 'none' | 'hour' | 'both';
    minuteHandParked: boolean; // true = drawn at 12 and never moves (t2.4)
    numerals: boolean;
    minuteMarks: boolean;
    minuteLabels: boolean;     // the 5 / 10 / 15 … ring
    pastToShade: boolean;
    showDigital: boolean;
  };
  preview?: 'quarterTurn';     // t4.1 only: animate, then ask
  badge: string;               // badge id = level id
}
```

Rules the schema encodes:

- `round[]` is **ordered**, and any level containing a `read` step places it before its `set`
  steps. Reading first is a product decision (2026-10-23), not an accident of ordering.
- `itemsPerRound` is derived: `round.reduce((n, s) => n + s.items, 0)`.
- `minutes[]` values are always multiples of 5 in v1.
- `face.hands === 'none'` forbids `read` and `set` steps (validator enforces).

### 4.2 Clock geometry — the invariant

```ts
minuteAngle(deg) = minutes * 6;                        // 0° = 12 o'clock position
hourAngle(deg)   = (hour % 12) * 30 + minutes * 0.5;   // geared: continuous, never snapped
```

Reference values the tests must assert:

| Time | Hour angle | Note |
| --- | --- | --- |
| 3:00 | 90° | hand on the numeral |
| 3:30 | **105°** | exactly halfway 3→4; the central teaching point |
| 12:30 | **15°** | past the 12 — that is why it reads *twelve*, not one |
| 9:45 | 292.5° | just short of the 10 |
| 1:05 | 32.5° | small creep, still after the 1 |

Tolerance in tests: ±0.01°. At render time the hour hand is never rounded to a numeral.

### 4.4 Level integrity rules (validator, `npm run validate:levels`)

1. ids unique, tiers contiguous from 0, every tier 0–4 has ≥1 level.
2. `round[]` sums to a number in `[4, 12]`.
3. any `read` step precedes every `set` step.
4. every value in `minutes[]` is a multiple of 5 in v1.
5. a level with 10 items must offer ≥4 distinct times (hour × minute combinations, after `hours[]`
   filtering); otherwise the round cannot avoid immediate repeats.
6. `hands: 'none'` ⇒ no `read`/`set` steps; `hands: 'hour'` ⇒ no `set` step that moves a minute hand.
7. every audio key referenced exists in the manifest, for every enabled locale.
8. **no tier turns two difficulty knobs at once** relative to its predecessor (content,
   representation, task) — the check that encodes the pedagogy.

## 5. Screens

### 5.1 Setup (adult)

Header pills: `Level ▾` · `🔊 − / +` · `A− / A+` · `EN / 粵`.

- Level panel: tiers as rows, levels as pills. All selectable. The next uncleared level is
  highlighted *suggested*; nothing is locked.
- Name field: optional, free text, stored locally only (AC-21).
- Badge shelf: one badge per cleared level, drawn as a small clock face showing that level's
  signature time; unearned badges are outlines.
- `Start` is the single primary action. With no prior state, the default level is `t0.1`.

### 5.2 Play

```
prompt (icon + short words, always spoken)
   ↓
content box: the clock (or sequence strip / buildable face), pale-yellow, teal border
   ↓
pad row: [ ✓ Got it ] [ ✗ Not yet ]     — read tasks
          [ Done ]                       — set / order / build / choose(auto)
   ↓
progress track: 10 steps, one per correct answer
   ↓
footer: [ Change level ]
```

- No timer, no auto-advance, no score visible to the child.
- Streak `🔥 n in a row · best n` appears only above 0.
- Celebration overlay on track completion; dismissible; fires again in the next round.

### 5.3 Summary

✓ of N, the level's badge if cleared this round, `Again` and `Change level`. No percentage, no
grade, no comparison to a previous attempt.

## 6. Behaviour rules

| # | Rule |
| --- | --- |
| B1 | A round plays the level's `round[]` in order. |
| B2 | A missed item re-enters the queue **at least 3 positions later** and not immediately. |
| B3 | `read` items are marked by the adult only (✓ / ✗). No automatic marking. |
| B4 | `set` items are evaluated by the app (hand within 6° of target, or hour hand within 6° and minute hand within 6°); the adult still presses `Done`. |
| B5 | `choose` / `order` / `tap` / `build` are evaluated by the app. `build` passes at ≥10 of 12 numerals within 12° of ideal. |
| B6 | **Clearing a level** = ≥80% of items correct in one round, and only then is the badge awarded. |
| B7 | Two consecutive clears highlight the next level as suggested. No automatic progression. |
| B8 | Nothing is ever locked, including levels above the child's current tier. |
| B9 | The celebration fires on every completed track, every round — dismissal is remembered per milestone, not as a boolean. |
| B10 | The "not yet" verdict is never shown to the child as a failure: the face stays, no red cross appears on the clock, no sound plays. |
| B11 | Every prompt is spoken on arrival, guarded by an item key so a re-render does not re-speak it. A speaker button repeats on demand. |

## 7. Language

**v1 ships English by default with a Cantonese toggle.** The toggle is a header pill, persisted,
and switches *audio and the prompt text* together; the clock face itself is unchanged.

- `en` — British English: "three o'clock", "half past two", "quarter to four", "twenty-five past
  four". Matches the UK ladder.
- `yue` — Cantonese. **Phrase table requires a native check before audio generation.**
  HK colloquial clock reading is not a word-for-word translation of the English: `三點半` is
  half past three, but `三點三` is used for 3:15 and `三點九` for 3:45 (the `字` = five-minute
  unit), while school/textbook Cantonese may prefer `三點十五分` / `三點四十五分`. Both are in
  circulation. The phrase table is therefore a reviewed artefact, not generated text — see §14 R1.

Storage of the choice is per device, not per language environment.

## 8. Storage

`localStorage`, one namespace `clock.v1.`:

| Key | Type | Meaning |
| --- | --- | --- |
| `clock.v1.profile` | `{ name?: string }` | optional name, locally typed |
| `clock.v1.level` | `string` | last level id |
| `clock.v1.locale` | `'en' \| 'yue'` | audio/prompt language |
| `clock.v1.volume` | `number` | 0.3–1.0, five steps |
| `clock.v1.size` | `number \| null` | `null` = stylesheet `clamp()` |
| `clock.v1.badges` | `string[]` | cleared level ids |
| `clock.v1.streak` | `{ best: number }` | best streak only |

No other persistence. Clearing site data resets everything; that must not break the app.

## 9. Audio

- Pre-generated, single voice per locale, committed to `public/audio/<locale>/`.
- English voice: `en-GB-SoniaNeural`, rate −8%, mono 22.05 kHz, normalised to −14 LUFS.
- Cantonese voice: to be chosen once the phrase table is signed off (`zh-HK` neural voice).
- Files: 48 time phrases (en) + prompts + praise. Browser speech synthesis is a fallback only, and
  a missing file must not fail the round.
- The manifest is generated, not hand-written, and the validator checks every referenced key.

## 10. Acceptance criteria

Numbered for the test map. Every one is `Given / When / Then`.

### Geometry

**AC-01** Given a clock showing 3:30, when the face renders, then the hour hand is at 105° (±0.01°)
and the minute hand at 180°.

**AC-02** Given a clock showing 12:30, when the face renders, then the hour hand is at 15° — past the
12, not on it.

**AC-03** Given any time, when the face renders, then `hourAngle === (hour % 12) * 30 + minute * 0.5`
— the hour hand is never snapped to a numeral.

**AC-04** Given a level with `face.hands: 'hour'`, when a question renders, then no minute hand, no
minute marks and no minute labels exist in the DOM.

### Content

**AC-05** Given `src/levels.json`, when `npm run validate:levels` runs, then it passes, and it fails
if any of §4.4's eight rules is violated.

**AC-06** Given level `t3.2`, when its round is built, then the first step is a `read` step and no
`set` step precedes it.

**AC-07** Given any level with 10 items, when a round is generated, then no time repeats within 3
positions of itself.

### Flow and marking

**AC-08** Given a `read` item, when the child answers, then only `✓ Got it` and `✗ Not yet` are
offered, and the app does not evaluate anything itself.

**AC-09** Given a `set` item, when the child drags the hand to within 6° of the target, then the app
records it correct without an adult verdict, and `Done` advances.

**AC-10** Given a wrong answer at item 2 of 10, when the round continues, then that item reappears at
position ≥5.

**AC-11** Given a completed round, when the summary renders, then it shows ✓ of N, offers `Again`
and `Change level`, and shows no percentage or grade.

**AC-12** Given a `build` item with 10 of 12 numerals within 12° of ideal, when the child presses
Done, then the item is recorded correct.

### Rewards

**AC-13** Given a round where the track completes, when the last item is marked, then the celebration
overlay appears.

**AC-14** Given a celebration dismissed in the previous round, when the next round's track completes,
then the celebration appears again.

**AC-15** Given a round of 7 of 10 correct, when it ends, then **no badge** is awarded and the level
is not marked cleared.

**AC-16** Given a round of 8 of 10 correct on a previously uncleared level, when it ends, then the
badge is added to `clock.v1.badges` and the shelf shows it filled on the setup screen.

**AC-17** Given two consecutive clears of a level, when the summary is dismissed, then the next level
is highlighted as *suggested*, and no level is locked.

### Language

**AC-18** Given `clock.v1.locale === 'yue'`, when a round starts, then prompts and time phrases are
spoken from the Cantonese manifest and the prompt text is the Cantonese form.

**AC-19** Given a time with no audio file in the active locale, when it is spoken, then the app falls
back without failing the round, and the occurrence is not shown to the child.

**AC-20** Given the locale toggle is pressed mid-session, when the next item appears, then the new
locale is used and the choice persists across reloads.

### Storage and guardrails

**AC-21** Given a name typed at setup, when the app is reloaded, then the name is still shown, and
`grep` of the built bundle and the repo finds no name string (it exists only in `localStorage`).

**AC-22** Given cleared site data, when the app loads, then it opens at `t0.1` with no badges and no
error.

**AC-23** Given the built `dist/`, when `npm run guardrail:scan` runs, then it fails if any tracked
file contains an email address, a private IP, a token, or one of the project's banned child-data
strings.

**AC-24** Given the app is loaded with the network disabled after first load, when a full round is
played, then it completes — no runtime network calls.

## 12. Build order

1. **Geometry + level data + validator** — `clock.test.ts` red first, then green. No UI.
2. **Face renderer** (SVG) against the geometry, with a static harness page.
3. **Play screen for `choose` and `order`** — the T0/T1 tasks, which need no clock at all. This
   makes the app playable at the bottom of the ladder early.
4. **Play screen for `read` and `set`**, with the adult verdict pad.
5. **Rewards** — track, celebration, badges, streak.
6. **Audio**, English, generated from the level data.
7. **Cantonese phrase table + audio**, after the native check.
8. **`build` and `tap` tasks** (T1.1, t1.3, t1.4).
9. **Cloudflare Pages deploy** with the custom domain.

## 13. Deploy

**Cloudflare Pages directly** — no GitHub Pages step. POC for personal and family/friends use.
Static build, `base: './'`, no server. Custom domain `clock.zt489.com` per the existing
DNS-01 pattern; the deploy itself follows the `cloudflare-pages-deploys` runbook (scoped API token,
wrangler, real-fetch verification — not just a green dashboard).

## 14. Risks and open items

**R1 — The Cantonese phrase table is not a translation job.** HK colloquial usage (`三點三` = 3:15)
and school/textbook usage (`三點十五分`) differ, and a wrong choice teaches the wrong form for his
classroom. **Action: a short table (12 hours × 4 phases = 48 phrases) goes to Kathy for sign-off
before any Cantonese audio is generated.** Until then the toggle exists but the locale is marked
`yue: unreviewed` and English is the default.

**R2 — Audio count vs. build time.** 48 English phrases is ~10 minutes of generation. Fine. The
Cantonese set doubles it and needs a voice choice.

**R3 — `build` task tolerance.** 12° may be too tight for a four-year-old's fine motor control on a
tablet. Start at 12°, and if he cannot pass it, widen to 15° — record whichever lands.

**R4 — The one thing that cannot be tested here.** Whether he actually enjoys it. First real
feedback decides more than this spec does.
