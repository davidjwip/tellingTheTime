## 1. Purpose

A supervised web page that helps a four-year-old learn to read an analogue clock, in the same
shape as the existing maths and spelling pages: one large clock, one question spoken aloud, an
adult who marks the answer.

Grounded in `research/` — the teaching order in `02-progression-ladder.md`, the tiering in
`04-game-design-brief.md`.

**Success for v1** is not "he can read a clock". It is: he asks to play it, he can operate it at
T0–T2 without help beyond the marking, and the adult can see which level he is on.

## 2. Non-goals

- No accounts, no backend, no network calls at runtime, no analytics.
- No elapsed-time, 24-hour or Roman-numeral work (that is T7).
- No timers, lives, coins, leaderboards, or daily-streak mechanics.
- No assessment output, report card, or progress email. The adult can see the level and the badges;
  that is the whole reporting surface.
- **No reading required of the child.** Where a task's natural material is text (day names in
  t0.4, day cards in t0.1), the material is pictorial and the prompt is spoken; the adult may read
  a label aloud. See R6.

## 3. Users

**Two people, one screen.** The child answers; the adult operates every control, presses every
verdict, and chooses when to stop. The app must never assume the child can read, type, or navigate.

## 4. Content model

### 4.1 Level schema

One declarative file, `src/levels.json`, drives everything. **No level behaviour may live in the
view layer** — that is an acceptance criterion (AC-10).

```ts
type Task = 'order' | 'choose' | 'read' | 'set' | 'build' | 'tap';

/** One presented item. What an "item" *is* depends on the task — see 4.2. */
interface RoundStep { task: Task; items: number; }   // ordered: reading comes first

/** Non-clock content, for the eight levels below tier 2. */
type Content =
  | { kind: 'dayCards';    count: 3 }          // t0.1  breakfast, bus, bath
  | { kind: 'dayStrip' }                       // t0.2  yesterday | today | tomorrow
  | { kind: 'durationPair' }                   // t0.3  two events, shared start
  | { kind: 'weekTiles';   count: 7 }          // t0.4  day tiles, pictorial
  | { kind: 'numberOrder'; from: 1; to: 12 }   // t1.1  tap the numerals in order
  | { kind: 'wrap' }                           // t1.2  what comes after 12
  | { kind: 'fivesRing';   to: 60 }            // t1.3  5, 10, … 60 round the rim
  | { kind: 'buildFace';   numerals: 12 };     // t1.4  drag numerals into place

interface Level {
  id: string;                       // 't3.2' — stable; tests, storage, badges
  tier: 0 | 1 | 2 | 3 | 4 | 5 | 6;
  title: { en: string; yue?: string };          // adult-facing only
  round: RoundStep[];               // ordered; sums to the round length
  content: Content | { kind: 'clock' };         // clock levels take times from hours/minutes
  minutes?: number[];               // clock levels only; multiples of 5 in v1
  hours?: number[];                 // optional subset, e.g. [12, 3, 6, 9]
  face?: {                          // absent when content.kind !== 'clock'
    hands: 'none' | 'hour' | 'both';
    minuteHandParked: boolean;      // true = drawn at 12 and never moves (t2.4)
    numerals: boolean;
    minuteMarks: boolean;           // reserved: T5+ only
    minuteLabels: boolean;          // the 5 / 10 / 15 … ring
    pastToShade: boolean;           // reserved: T5+ only
    showDigital: boolean;           // reserved: T6 only
  };
  preview?: 'quarterTurn';          // t4.1 only: animate, then ask
  badge: { time: [number, number] }; // the clock face drawn on the badge, e.g. [3, 30]
}
```

Rules the schema encodes:

- `round[]` is **ordered**; any level containing both places `read` before `set` (product decision
  2026-10-23, enforced by rule 3).
- Round length is derived: `round.reduce((n, s) => n + s.items, 0)`.
- `content.kind === 'clock'` ⇔ `minutes` is present. `face` is present whenever the level draws a
  face — which **includes T1**, where the numerals are drawn with `hands: 'none'`. Only the four
  faceless content kinds (`dayCards`, `dayStrip`, `durationPair`, `weekTiles`) omit it.
- `minutes[]` values are always multiples of 5 in v1.

### 4.2 What one "item" is, per task

Undefined in v1.0; normative now.

| Task | One item is | A round of 10 means |
| --- | --- | --- |
| `read` | one time shown, one verdict | 10 times |
| `set` | one time requested, hands dragged, one `Done` | 10 times |
| `choose` | one question with 2–3 options | 10 questions |
| `order` | one **complete ordering** of the card/tile set | 10 orderings |
| `tap` | one **complete lap** (all 12 taps) | 10 laps |
| `build` | one **complete face build** (12 numerals placed) | 10 builds |

`items` counts presented items, never taps or drags. A build round of 3 items is 36 numeral
placements and is therefore *not* a 10-step track — see §5.2 and R5.

### 4.3 Clock geometry — the invariant

```ts
minuteAngle(deg) = minutes * 6;                        // 0° = 12 o'clock position
hourAngle(deg)   = (hour % 12) * 30 + minutes * 0.5;   // geared: continuous, never snapped
```

| Time | Hour angle | Note |
| --- | --- | --- |
| 3:00 | 90° | hand on the numeral |
| 3:30 | **105°** | exactly halfway 3→4; the central teaching point |
| 12:30 | **15°** | past the 12 — that is why it reads *twelve*, not one |
| 9:45 | 292.5° | just short of the 10 |
| 1:05 | 32.5° | small creep, still after the 1 |

Test tolerance ±0.01°. At render time the hour hand is never rounded to a numeral.

### 4.5 Level integrity rules (`npm run validate:levels`)

1. ids unique; tiers contiguous from 0; every tier 0–4 has ≥1 level.
2. `round[]` sums to a number in `[3, 12]`.
3. any `read` step precedes every `set` step.
4. every value in `minutes[]` is a multiple of 5 in v1; `minutes[]` non-empty on clock levels.
5. **distinct-content rule**, applied per content type: `read`/`set`/`choose` **clock** levels need
   distinct times (or pairs) ≥ `min(4, round length)` — v1.4 said `min(4, available)`, which is
   circular and made the rule vacuous; corrected in v1.5 while implementing it; `choose` **non-clock** levels need ≥2 distinct
   option-sets (t0.2's three positions, t0.3's eight pairs); `order`/`tap`/`build` need ≥1 declared
   `content`. **Counts are fixed by §4.4**: `dayCards.count = 3`, `weekTiles.count = 7`,
   `buildFace.numerals = 12`, `numberOrder` is 1–12, `fivesRing.to = 60`, and `durationPair` needs
   at least as many distinct pairs as it has items. **A non-clock level is never required to offer
   times** — v1.0's wording failed its own committed data (`t0.2`, `t1.2`).
6. **content ↔ face**: only clock levels may declare `minutes` or `hours`; `face` is required
   whenever the level draws a face — including T1's numerals-only faces — and forbidden for the four
   faceless kinds. `face.hands === 'none'` ⇒ no `read`/`set` steps; `face.hands === 'hour'` ⇒ any
   `set` step needs a single fixed minute (there is nothing for a minute hand to show). The reserved
   fields (`minuteMarks`, `pastToShade`, `showDigital`) must be `false` in v1, and `minuteLabels`
   requires `hands: 'none'`.
7. every audio key referenced exists in the manifest, for every **enabled** locale.
8. **declared-knob rule** (revised in v1.4 — the v1.1 wording was wrong). Every level declares its
   `{content, representation, task}` triple, tabulated in §4.6. The validator checks three things:
   (i) the declaration matches the level's own config; (ii) **within T2–T4 the number of hands is
   non-decreasing** — hour-only may become both, never the reverse. *"The minute hand appears at
   most once per tier" is a consequence of (ii), not a separate check: a second reveal would need an
   intervening re-conceal, which (ii) already forbids. v1.4 stated it as a third clause and the
   first implementation ranked hands by whether they move rather than how many there are, which
   made the clause both redundant and wrong.* Tier boundaries are exempt (a new tier is meant to
   change content and representation together). **Task weights may vary freely within a tier** — a
   round mixing read and set is pacing, not a difficulty knob. The old "exactly one knob per step"
   claim was aspirational and is false of the committed level set; do not reintroduce it as a
   validator heuristic.

## 5. Screens

**The visual layer is not specified in this file.** Colour, type, spacing, radii, shadows,
breakpoints, the header pill set, the goal track, the celebration overlay and the parity gate are
all in [`design-parity.md`](design-parity.md), read from the maths app's own `style.css` and
`App.vue`. Layout regions below name the reference classes they reuse.

### 5.1 Setup (adult)

Header pills, in the reference's own order and styling (`design-parity.md` §4.1):
`🔢 Level` · `EN / 粵` (segmented pair, like `+`/`−`) · `🔊` · `👤`.

- `🔢 Level` opens a popup styled exactly like the maths app's `.limit-popup`.
- `👤` opens the profile panel: optional name (max 20 chars) and the **same eight mascots**, per
  `design-parity.md` §4.6. There is no `A− / A+` control — the reference has none.
- Level panel: tiers as rows, levels as pills. **All selectable on a fresh install.** The next
  uncleared level is highlighted *suggested*; nothing is locked.
- Name field: optional, free text, `localStorage` only (AC-31).
- Badge shelf: one badge per cleared level, drawn from `badge.time`; unearned badges are outlines.
  Styled as a 60×60 tile in the `.mascot-btn` treatment (`design-parity.md` §7).
- `Start` is the single primary action. Fresh-install default level: `t0.1`.

### 5.2 Play

```
prompt (icon + short words, always spoken)
   ↓
content box: clock / sequence strip / buildable face — pale-yellow, teal border
   ↓
pad row: [ ✓ Got it ] [ ✗ Not yet ]     — read
          [ Done ]                       — set / order / build / (choose auto-advances)
   ↓
progress track: N steps, N = the round's item count (10 on every T2–T4 level)
   ↓
footer: [ Change level ]
```

- **Track length equals the round's item count.** 10 on every clock level; 3–8 on the six
  non-10-item levels. It is derived, not hardcoded.
- No timer, no auto-advance, no score visible to the child.
- Streak `🔥 n in a row · best n`, shown only above 0.
- Celebration on track completion; dismissible; fires again in the next round.

### 5.3 Summary

✓ of N, the level's badge if cleared this round, `Again` and `Change level`. No percentage, no
grade, no comparison to a previous attempt.

## 6. Behaviour rules

| # | Rule |
| --- | --- |
| B1 | A round plays the level's `round[]` in order; its length is the sum of the steps. |
| B2 | A missed item re-enters the queue **at least 3 positions later**, never immediately after itself. |
| B3 | `read` items are marked by the adult only (✓ / ✗). No automatic marking. |
| B4 | `set` items are evaluated by the app: **minute hand within 3°** and **hour hand within 3°** of target. The adult still presses `Done`. |
| B5 | At `:30` a dragged hour hand **snaps to the halfway angle** between the two numerals; it can never come to rest on a numeral. |
| B6 | `choose` / `order` / `tap` / `build` are evaluated by the app. `build` passes when ≥10 of 12 numerals are within 12° of ideal. |
| B7 | **Clearing a level** = correct items ≥ `round(0.8 × N)` in one round, and only then is the badge awarded. N=10 → 8; N=6 → 5; N=4 → 3. |
| B8 | Two consecutive clears highlight the next level as *suggested*. No automatic progression. |
| B9 | Nothing is ever locked, including levels above the current tier. |
| B10 | The celebration fires on every completed track, every round — dismissal is remembered per milestone, not as a boolean. |
| B11 | A `✗` leaves the clock exactly as it was: no red mark on the face, no error sound, no shake, no change of screen. |
| B12 | Every prompt is spoken on arrival, guarded by an item key so a re-render does not re-speak it. A speaker button repeats on demand. |
| B13 | Volume persists across five steps (30–100%, default 85%); size defaults to the stylesheet `clamp()` and only changes when an adult presses the size buttons. |
| B14 | Best streak persists across sessions; the current streak resets per round. |
| B15 | Interactive targets are ≥96 px in their smallest dimension, and the ✓ / ✗ pair is widely separated. |
| B16 | **`choose` distractors are specified, not improvised.** t3.1/t3.2 present one face with the hour hand *on* a numeral and one *between* numerals, same hour. t4.1 presents the same time at `:15` against `:45`, or the same phase one hour off. t1.2 presents adjacent hours including the 12→1 wrap. t0.2/t0.3 present the two plausible alternatives, never a nonsense option. |
| B17 | Best streak persists across rounds and sessions; the current streak resets only when a round ends. |

## 7. Language

**English default, Cantonese toggle.** The toggle is a header pill, persisted, and switches audio
and prompt text together; the clock face is unchanged.

- `en` — British English: "three o'clock", "half past two", "quarter to four", "twenty-five past
  four". Matches the UK ladder.
- `yue` — **settled 2026-10-23: colloquial throughout.** `三點鐘` / `三點半` / `三點三` (3:15) /
  `三點九` (3:45), on the `字` five-minute unit. Table:
  [`data/phrases-yue.md`](../data/phrases-yue.md), machine form
  [`data/phrases-yue.csv`](../data/phrases-yue.csv) — 48 time phrases + 8 prompts.
  **Cantonese is internally consistent in a way English is not:** the hour spoken is always *the
  hour the hand has just passed* — 3:45 is `三點九`, never `四點九`. So the "name the next hour"
  difficulty in t4.3 does not exist in this locale; that rung is genuinely easier, and AC-47
  protects its answer key. A phrase later found awkward is a CSV edit, not a code change.

## 8. Storage

`localStorage`, one namespace `clock.v1.`:

| Key | Type | Meaning |
| --- | --- | --- |
| `clock.v1.profile` | `{ name?: string }` | optional name, locally typed |
| `clock.v1.level` | `string` | last level id |
| `clock.v1.locale` | `'en' \| 'yue'` | audio/prompt language |
| `clock.v1.volume` | `number` | 0.3–1.0, five steps |
| `clock.v1.size` | `number \| null` | reserved — **no UI in v1** (the reference has no size control); `null` = stylesheet sizing |
| `clock.v1.badges` | `string[]` | cleared level ids |
| `clock.v1.streak` | `{ best: number }` | best streak only |

No other persistence. Clearing site data resets everything; that must not break the app.

## 9. Audio

- Pre-generated, single voice per locale, committed to `public/audio/<locale>/`.
- English: `en-GB-SoniaNeural`, rate −8%, mono 22.05 kHz, −14 LUFS.
- Cantonese voice chosen once the phrase table is signed off (§7).
- Files: 48 English time phrases + 8 prompts + short praise (`data/phrases-yue.md` fixes the eight). Browser speech synthesis is a
  fallback only; a missing file must not fail the round.
- The manifest is generated from the level data, not hand-written, and rule 7 checks it.

## 10. Acceptance criteria

Single-purpose, `Given / When / Then`, stable numbering. *(new)* = added in v1.1; *(rev)* =
materially rewritten.

**Testability rule:** where a criterion carries more than one assertion, §11's test map lists one
row **per assertion**. Several criteria here intentionally bundle read/write/draw facets of one
behaviour (14 of them, flagged in review); the test map is the mechanism that keeps each assertion
independently checkable without renumbering the spec.

### Geometry

**AC-01** Given a clock showing 3:30, when the face renders, then the hour hand is at 105° (±0.01°)
and the minute hand at 180°.

**AC-02** Given 12:30, when the face renders, then the hour hand is at 15° — past the 12, not on it.

**AC-03** Given any time, when the face renders, then `hourAngle === (hour % 12) * 30 + minute * 0.5`
— never snapped to a numeral.

**AC-04** Given a level with `face.hands: 'hour'`, when a question renders, then no minute hand, no
minute marks and no minute labels exist in the DOM.

**AC-05** *(new)* Given any `:30` time on a two-hand face, when the face renders, then the hour hand
is strictly between two numerals — not within 2° of either.

### Content and model

**AC-06** *(rev)* Given the committed `src/levels.json`, when `npm run validate:levels` runs, then it
exits 0 — including for the eight non-clock levels.

**AC-07** Given a level file with any single violation of §4.5's eight rules, when the validator
runs, then it fails, naming the level id and the rule number.

**AC-08** *(rev)* Given level `t2.1` (`R×6, S×4`), when its round is built, then every `read` step
precedes every `set` step.

**AC-09** *(rev)* Given any round, when it is generated, then no time repeats within 2 positions of
itself.

**AC-10** *(new)* Given the 20 levels in `levels.json`, when the app renders each one, then every
level is renderable from its declared `content` and `face` alone — no level-id-specific branch in
the view layer.

**AC-11** *(new)* Given level `t3.1`, when a pair is presented, then exactly one face has its hour
hand on a numeral and the other has it strictly between two numerals.

**AC-12** *(new)* Given a `:30` face with the hour hand between 2 and 3, when the adult marks, then
"half past two" is recorded correct and "half past three" is recorded not yet.

### Flow and marking

**AC-13** Given a `read` item, when the child answers, then only `✓ Got it` and `✗ Not yet` are
offered, and the app evaluates nothing itself.

**AC-14** *(rev)* Given a `set` item, when both hands are within 3° of the target, then the app
records it correct and `Done` advances.

**AC-15** *(new)* Given a `set` item at `:30`, when the child drags the hour hand to any point
between the two numerals, then on release it snaps to the halfway angle.

**AC-16** *(rev)* Given a wrong answer at item 2 of a round, when the round continues, then that item
reappears no earlier than position 5.

**AC-17** Given a completed round, when the summary renders, then it shows ✓ of N, offers `Again`
and `Change level`, and shows no percentage or grade.

**AC-18** Given a `build` item with 10 of 12 numerals within 12° of ideal, when the child presses
`Done`, then the item is recorded correct.

**AC-19** *(new)* Given a `read` item marked `✗ Not yet`, when the verdict is recorded, then the
clock's geometry and styling are unchanged, no error sound plays, and the screen does not advance.

### Rewards

**AC-20** Given a round where the track completes, when the last item is marked, then the
celebration overlay appears.

**AC-21** Given a celebration dismissed in the previous round, when the next round's track
completes, then the celebration appears again.

**AC-22** *(rev)* Given a round of N items ending below `round(0.8 × N)` correct, then no badge is
awarded and the level is not marked cleared — tested at N=10 (7 correct) and N=4 (2 correct).

**AC-23** Given a round at or above the threshold on a previously uncleared level, when it ends,

## 19. Amendment v1.5 — rounds ask only what can be presented (2026-10-23)

The spec above describes a round as "the sum of its steps". The build cannot yet present five of the
six task kinds, and asking a four-year-old a question he cannot act on is worse than not asking it,
so the implementation diverges deliberately and in one place. This section is the authority for that
divergence; where §4, §5.2 and B1 disagree with it, this section wins until the missing screens land.

**19.1 Answerable tasks.** `SUPPORTED_TASKS` in `src/engine.ts` lists the task kinds with a screen.
Today it is `{read}`. Steps whose task is unsupported are dropped when the round is built. The
level data keeps them untouched, so nothing is retyped when a screen arrives — the set membership
changes, and the round grows back.

**19.2 Round length.** `session.total` is the length of the built queue, not the sum of the level's
steps. `t2.2` is therefore six questions and clears at five (B7 still holds: `round(0.8 × 6) = 5`).
The goal track shows the built length. The celebration interpolates it.

**19.3 The shelf.** `src/picker.ts` offers a level only when at least `MIN_ITEMS` (4) answerable
questions remain, and says what the unavailable ones are waiting for. The pre-clock tiers are
unavailable today; the shelf states that rather than presenting a button that does nothing.

**19.4 Practice and the B2 gap.** A miss re-enters the queue at least three positions later. When
fewer than three items remain, the round extends with practice drawn from the same level. Practice
is not assessed: it never fills a step on the track, it is never re-queued when missed, and a single
round may invent at most `MAX_FILLERS` (6) of them, so a child who answers nothing still reaches the
end of the round in bounded time.

**19.5 What must be restored.** When hand-dragging lands, `set` returns to `SUPPORTED_TASKS` and the
set-task screen returns with it; rounds return to their data length and the thresholds return with
them. Nothing in this section should outlive that.

### 19.6 Amendment v1.6 — the round is a goal, not a length (2026-10-23)

Dave's instruction: *"target is to keep going until we try to get 10 correct answers or the person
who is supervising the child assists or calls it that we don't need to get to 10. If a child takes a
level they can't do but tries and constantly misses that OK."*

This supersedes 19.2 and the practice ceilings in 19.4.

- A round ends when the child has **ten right answers**, or when the adult ends it. There is no
  length, no failure state, and nothing counts misses.
- Questions keep coming: once the level's planned items are used, more are drawn from the same
  level. Practice is unlimited, because needing several goes at a dial is the normal case at four.
- A missed item returns three places later, every time it is missed — no cap on attempts.
- The track shows ten steps and fills with right answers, so it always fills eventually.
- The summary reports right answers, the goal, first-attempt right answers and the best streak. It
  says **"Nice work today!"** when the adult calls it early, never "good try" and never a score.
- `firstPassCorrect` is reported for the adult's interest and gates nothing.

### 19.7 Amendment v1.7 — clauses superseded by 19.6 (2026-10-23)

B1, B7, AC-22, AC-26 and §5.2 still describe the 0.8 × N accuracy threshold and "track length =
item count". **They are superseded by 19.6**: a round ends at ten right answers, the track is the
goal, and nothing is measured against accuracy. Read those clauses as history; the code follows 19.6.

19.6 also promised that the summary would report first-attempt figures. It does not, deliberately: a
"first try" count on a child's screen is a comparison he can read. `firstPassCorrect` is recorded,
displayed nowhere, and kept for an adult-facing view if one is ever built.

### 19.8 Amendment v1.8 — audio as recorded (2026-10-23)

§9 described runtime speech synthesis with a fallback and an −8% rate. The build records clips
instead: `en-GB-SoniaNeural` and `zh-HK-HiuMaanNeural` at **−12%**, 24 kHz mono mp3, generated by
`scripts/generate_audio.py` from `data/phrases.json`. There is no runtime synthesis and no fallback
voice — a missing clip fails the build, which is the only failure mode worth having.

The manifest records a sha256 per clip, and a test recomputes it. An existence check cannot tell a
correct clip from one generated for last week's wording, and that is the drift that would reach the
child as a wrong answer.

## 20. Amendment v1.9 — one door per tier, and a bank that opens downwards

Decided 2026-10-24, after the first week of the site being live. The shelf listed all twenty level
buttons, four under each tier. That reads as a curriculum document, not a game: an adult standing
behind a four-year-old has to choose between "O'clock: the four anchors" and "Two hands, minute hand
parked" before the child has seen a clock. The exercises are real, but they are the *author's* unit of
work, not the player's.

### AC-52 — one entry per tier

The shelf shows exactly **one playable entry per tier** that has playable content, labelled with the
tier title ("Before the clock", "Numbers and the dial", "O'clock", "Half past", "Quarter past and to").
The four exercise names within the tier are **not** buttons. They are printed as small quiet text
under the tier heading, and also carried as the entry's `title` and `aria-description` — because a
`title` attribute never opens on an iPad, which is the device this is played on (review of PR #14).

A tier with no playable content is not shown at all. Today that is tier 1.

### AC-53 — a tier round is drawn, not enumerated

Selecting a tier starts a round of ten correct answers (unchanged, AC-30) whose items are drawn from
the **combined bank of every playable level in that tier**, in an order the child cannot predict:

- item order is a seeded shuffle per session, and two sessions of the same tier must not produce the
  same order;
- the no-repeat window (`REQUEUE_GAP`) applies across the whole tier, not per level;
- each item keeps the level it came from, so `?level=t2.2` still plays exactly that level (the deep
  link remains the debugging and testing path).

### AC-54 — the bank opens downwards, one item in four

Of the ten items in a tier round, **one in four (rounded to the nearest whole item) is drawn from a
tier strictly below the chosen one**, provided that lower tier has playable content. Lower-tier items
are revision: they are drawn from the same combined-bank mechanism, never duplicated within the round,
and never placed as the first item — the child opens on the tier they chose.

If no lower tier is playable, the round is drawn wholly from the chosen tier. A tier-0 round has no
lower tier and is unaffected.

### AC-55 — the language control reads as a setting, not a game control

The EN/粵 control is a segmented setting, not two loose buttons: both options are always visible, the
active one is tinted (English green `#4ecdc4`, Cantonese red `#ff6b6b`, matching the maths app's
operator toggle) and marked `aria-pressed`, and the inactive one is neutral. The tint must change on
selection **without a redraw that loses the round** (AC-44, 19.8).

## 22. Amendment v1.11 — tap the dial, count in fives, and a written register

Two requests from Dave after Kathy played it (2026-10-24): a "proper" Cantonese read alongside the
colloquial one, and the numeral-to-minutes bridge — *"when the minute hand is at the 1, 2 o'clock
times, we need to be saying 5, 10 ... we need to get him to associate 60 minutes in an hour and the
multiples of 5 vs the hour numbers."*

The taxonomy already names this misconception — *"reads the numeral the minute hand points at as the
minutes (points at 5 → '5 past', not 25 past)"* — and the scaffold already exists: `clockFace.ts` can
draw the 5/10/…/60 ring, `t1.3` exists in the level data, and both are dark because no screen can ask a
child to touch the dial.

### AC-60 — the tap screen

A `tap` item presents a face the child touches directly. The task is **one complete lap**: the values
must be tapped in order, and a wrong touch does not advance the lap.

- the lap's values come from the content: `numberOrder` → `from..to` step 1; `fivesRing` → 5, 10 … `to`.
- only the face is tappable — the numerals when the lap is over numerals, the 5-minute labels when the
  lap is over labels. A lap over labels ignores taps on numerals, and vice versa.
- a correct touch marks that value as done and stays marked for the rest of the lap.
- a wrong touch marks nothing and gives no verdict; the child simply tries again. There is no ✗ for a
  four-year-old hunting a number.
- finishing the lap is one correct item, and the round moves on.

`t1.1 Tap 1 to 12` and `t1.3 Count round in fives` become playable, and with them **tier 1 gets a door**.

### AC-61 — the numeral-to-minutes bridge

Two levels in a new tier 5, "Five minutes", because the ladder's Stage 7 is exactly this and it is not
reachable from tier 4:

- `t5.1 The rim is fives` — the 5/10/…/60 ring is visible. The question is a numeral: *"the hand is on
  the 4 — how many minutes is that?"* This is the association, made explicit.
- `t5.2 Five past, ten past` — the ring is hidden and the child reads five-minute times (`3:05`,
  `3:20`, `3:50`) where the numeral no longer gives the answer away.

Wording for five-minute times is *"five past three"*, not *"three oh five"*: the spoken form carries the
minute count, which is the thing being taught.

### AC-62 — the written register

A third audio locale, `yue-formal`, reads the clock in the **written** register rather than the spoken
one, per Kathy: *"refer to the Putonghua written style and not colloquial."*

| time | colloquial (`yue`) | written (`yue-formal`) |
| --- | --- | --- |
| 3:00 | 三點鐘 | 三時正 |
| 3:05 | 三點一個字 | 三時零五分 |
| 3:15 | 三點三 | 三時十五分 |
| 3:30 | 三點半 | 三時三十分 |
| 3:45 | 三點九 | 三時四十五分 |

Every chrono phrase carries a `yue-formal` column and every clip a `yue-formal` recording in the same
voice, so the toggle and the audio cannot disagree. The register is chosen in the grown-up row and
persists like the language.

### AC-63 — no chatter between questions

The app does not speak a generic prompt when a new item appears. *"Have a go"* is removed: a child who
hears it ten times a round learns to ignore the audio, and the words carry no information. What remains
is what carries meaning — the question itself for a read item, praise, encouragement, and the
celebration.

## 25. Amendment v1.14 — the setting screen exists, so `set` steps come back

AC-14 and AC-15 have been in the contract since v1.1 and have never been reachable: `set` was filtered
out of every round because there was no screen to drag a hand on. Four levels have been half-playable
ever since — `t2.2` is titled *O'clock: all twelve* and has only ever asked a child to read.

### AC-71 — a hand is dragged, not tapped

A `set` item shows the clock with both hands parked at 12 and the target time as the question. Each hand
carries an invisible grab-stroke along its length, so a four-year-old can catch it anywhere rather than
on a 4-pixel line.

- the minute hand snaps to the level's allowed minutes as it is dragged — a child cannot produce `4:07`
  on a level that asks for multiples of five;
- the hour hand follows the minute hand: at `:30` it sits halfway between numerals, per AC-15, and snaps
  to that halfway angle on release;
- dragging is a pointer gesture with capture, so a finger that leaves the dial keeps control of the hand
  it grabbed instead of dropping it mid-turn.

### AC-72 — `Done` marks it, and the app does the marking

A `Done` control sits under the dial and appears once either hand has been moved. Pressing it evaluates
both hands against the target with the **3° tolerance** AC-14 already fixes:

- within tolerance on both → the item is correct and the round moves on;
- otherwise → the item is a miss: encouragement, and it returns later in the round as every miss does.

The adult does not mark a `set` item. AC-13's pad belongs to `read` items, where only an adult can judge
whether a spoken answer was right; here the app knows the answer exactly.

### AC-73 — the set steps rejoin their rounds

`SUPPORTED_TASKS` gains `set`, so the steps that have been silently dropped come back:
`t2.1` and `t2.2` (o'clock), `t4.2` (quarter past) and `t4.3` (quarter to). `t2.3` *Make it o'clock* and
`t3.3` *Make it half past* become playable levels in their own right.

A level is only playable for `set` when its face draws both hands; rule 6 already refuses a `set` step on
`hands: 'none'`.
