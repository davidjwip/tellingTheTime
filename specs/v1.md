# specs/v1.md — clock game, version 1.1

**Status: DRAFT — awaiting approval.** Per `AGENTS.md`, a spec is approved only when Dave says so
in the project thread. No implementation code until then.

**v1.1** incorporates the independent review of v1.0 (deepseek-v4-pro, 2026-10-23): 1 blocker,
10 major, 6 minor findings. Every finding is dispositioned in §16 — nothing was waved through.

Scope: **tiers T0–T4** (20 levels). T5–T6 and T7 are out of scope but the data model accommodates
them without change.

---

## 1. Purpose

A supervised web page that helps a four-year-old learn to read an analogue clock, in the same
shape as the existing maths and spelling pages: one large clock, one question spoken aloud, an
adult who marks the answer.

Grounded in `research/` — the teaching order in `02-progression-ladder.md`, the tiering in
`04-game-design-brief.md`.

**Success for v1** is not "he can read a clock". It is: he asks to play it, he can operate it at
T0–T2 without help beyond the marking, and the adult can see which level he is on.

## 2. Non-goals

- No accounts, no backend, no network calls at runtime, no analytics.
- No elapsed-time, 24-hour or Roman-numeral work (that is T7).
- No timers, lives, coins, leaderboards, or daily-streak mechanics.
- No assessment output, report card, or progress email. The adult can see the level and the badges;
  that is the whole reporting surface.
- **No reading required of the child.** Where a task's natural material is text (day names in
  t0.4, day cards in t0.1), the material is pictorial and the prompt is spoken; the adult may read
  a label aloud. See R6.

## 3. Users

**Two people, one screen.** The child answers; the adult operates every control, presses every
verdict, and chooses when to stop. The app must never assume the child can read, type, or navigate.

## 4. Content model

### 4.1 Level schema

One declarative file, `src/levels.json`, drives everything. **No level behaviour may live in the
view layer** — that is an acceptance criterion (AC-10).

```ts
type Task = 'order' | 'choose' | 'read' | 'set' | 'build' | 'tap';

/** One presented item. What an "item" *is* depends on the task — see 4.2. */
interface RoundStep { task: Task; items: number; }   // ordered: reading comes first

/** Non-clock content, for the eight levels below tier 2. */
type Content =
  | { kind: 'dayCards';    count: 3 }          // t0.1  breakfast, bus, bath
  | { kind: 'dayStrip' }                       // t0.2  yesterday | today | tomorrow
  | { kind: 'durationPair' }                   // t0.3  two events, shared start
  | { kind: 'weekTiles';   count: 7 }          // t0.4  day tiles, pictorial
  | { kind: 'numberOrder'; from: 1; to: 12 }   // t1.1  tap the numerals in order
  | { kind: 'wrap' }                           // t1.2  what comes after 12
  | { kind: 'fivesRing';   to: 60 }            // t1.3  5, 10, … 60 round the rim
  | { kind: 'buildFace';   numerals: 12 };     // t1.4  drag numerals into place

interface Level {
  id: string;                       // 't3.2' — stable; tests, storage, badges
  tier: 0 | 1 | 2 | 3 | 4 | 5 | 6;
  title: { en: string; yue?: string };          // adult-facing only
  round: RoundStep[];               // ordered; sums to the round length
  content: Content | { kind: 'clock' };         // clock levels take times from hours/minutes
  minutes?: number[];               // clock levels only; multiples of 5 in v1
  hours?: number[];                 // optional subset, e.g. [12, 3, 6, 9]
  face?: {                          // absent when content.kind !== 'clock'
    hands: 'none' | 'hour' | 'both';
    minuteHandParked: boolean;      // true = drawn at 12 and never moves (t2.4)
    numerals: boolean;
    minuteMarks: boolean;           // reserved: T5+ only
    minuteLabels: boolean;          // the 5 / 10 / 15 … ring
    pastToShade: boolean;           // reserved: T5+ only
    showDigital: boolean;           // reserved: T6 only
  };
  preview?: 'quarterTurn';          // t4.1 only: animate, then ask
  badge: { time: [number, number] }; // the clock face drawn on the badge, e.g. [3, 30]
}
```

Rules the schema encodes:

- `round[]` is **ordered**; any level containing both places `read` before `set` (product decision
  2026-10-23, enforced by rule 3).
- Round length is derived: `round.reduce((n, s) => n + s.items, 0)`.
- `content.kind === 'clock'` ⇔ `minutes` and `face` are present; otherwise both are absent.
- `minutes[]` values are always multiples of 5 in v1.

### 4.2 What one "item" is, per task

Undefined in v1.0; normative now.

| Task | One item is | A round of 10 means |
| --- | --- | --- |
| `read` | one time shown, one verdict | 10 times |
| `set` | one time requested, hands dragged, one `Done` | 10 times |
| `choose` | one question with 2–3 options | 10 questions |
| `order` | one **complete ordering** of the card/tile set | 10 orderings |
| `tap` | one **complete lap** (all 12 taps) | 10 laps |
| `build` | one **complete face build** (12 numerals placed) | 10 builds |

`items` counts presented items, never taps or drags. A build round of 3 items is 36 numeral
placements and is therefore *not* a 10-step track — see §5.2 and R5.

### 4.3 Clock geometry — the invariant

```ts
minuteAngle(deg) = minutes * 6;                        // 0° = 12 o'clock position
hourAngle(deg)   = (hour % 12) * 30 + minutes * 0.5;   // geared: continuous, never snapped
```

| Time | Hour angle | Note |
| --- | --- | --- |
| 3:00 | 90° | hand on the numeral |
| 3:30 | **105°** | exactly halfway 3→4; the central teaching point |
| 12:30 | **15°** | past the 12 — that is why it reads *twelve*, not one |
| 9:45 | 292.5° | just short of the 10 |
| 1:05 | 32.5° | small creep, still after the 1 |

Test tolerance ±0.01°. At render time the hour hand is never rounded to a numeral.

### 4.5 Level integrity rules (`npm run validate:levels`)

1. ids unique; tiers contiguous from 0; every tier 0–4 has ≥1 level.
2. `round[]` sums to a number in `[3, 12]`.
3. any `read` step precedes every `set` step.
4. every value in `minutes[]` is a multiple of 5 in v1; `minutes[]` non-empty on clock levels.
5. **distinct-content rule**, applied per content type: for `read`/`set`/`choose` clock levels,
   distinct times (or pairs) ≥ `min(4, available)`; for `order`/`tap`/`build`, ≥1 distinct
   option-set and a declared `content`. **A non-clock level is never required to offer times** —
   v1.0's wording failed its own committed data (`t0.2`, `t1.2`).
6. `content.kind === 'clock'` ⇔ `minutes` and `face` present; `face.hands === 'none'` ⇒ no
   `read`/`set` steps; `face.hands === 'hour'` ⇒ no `set` step that moves a minute hand.
7. every audio key referenced exists in the manifest, for every **enabled** locale.
8. **one-knob rule**, scoped: *within a tier*, consecutive levels may change exactly one of
   {content, representation, task}. **Tier boundaries are exempt** — a new tier is by definition a
   simultaneous change of content and representation, and that is the design. Implemented as a
   declared reference table of knob-triples per level, not as a heuristic.

## 5. Screens

### 5.1 Setup (adult)

Header pills: `Level ▾` · `🔊 − / +` · `A− / A+` · `EN / 粵`.

- Level panel: tiers as rows, levels as pills. **All selectable on a fresh install.** The next
  uncleared level is highlighted *suggested*; nothing is locked.
- Name field: optional, free text, `localStorage` only.
- Badge shelf: one badge per cleared level, drawn from `badge.time`; unearned badges are outlines.
- `Start` is the single primary action. Fresh-install default level: `t0.1`.

### 5.2 Play

```
prompt (icon + short words, always spoken)
   ↓
content box: clock / sequence strip / buildable face — pale-yellow, teal border
   ↓
pad row: [ ✓ Got it ] [ ✗ Not yet ]     — read
          [ Done ]                       — set / order / build / (choose auto-advances)
   ↓
progress track: N steps, N = the round's item count (10 on every T2–T4 level)
   ↓
footer: [ Change level ]
```

- **Track length equals the round's item count.** 10 on every clock level; 3–8 on the six
  non-10-item levels. It is derived, not hardcoded.
- No timer, no auto-advance, no score visible to the child.
- Streak `🔥 n in a row · best n`, shown only above 0.
- Celebration on track completion; dismissible; fires again in the next round.

### 5.3 Summary

✓ of N, the level's badge if cleared this round, `Again` and `Change level`. No percentage, no
grade, no comparison to a previous attempt.

## 6. Behaviour rules

| # | Rule |
| --- | --- |
| B1 | A round plays the level's `round[]` in order; its length is the sum of the steps. |
| B2 | A missed item re-enters the queue **at least 3 positions later**, never immediately after itself. |
| B3 | `read` items are marked by the adult only (✓ / ✗). No automatic marking. |
| B4 | `set` items are evaluated by the app: **minute hand within 3°** and **hour hand within 3°** of target. The adult still presses `Done`. |
| B5 | At `:30` a dragged hour hand **snaps to the halfway angle** between the two numerals; it can never come to rest on a numeral. |
| B6 | `choose` / `order` / `tap` / `build` are evaluated by the app. `build` passes when ≥10 of 12 numerals are within 12° of ideal. |
| B7 | **Clearing a level** = correct items ≥ `round(0.8 × N)` in one round, and only then is the badge awarded. N=10 → 8; N=6 → 5; N=4 → 3. |
| B8 | Two consecutive clears highlight the next level as *suggested*. No automatic progression. |
| B9 | Nothing is ever locked, including levels above the current tier. |
| B10 | The celebration fires on every completed track, every round — dismissal is remembered per milestone, not as a boolean. |
| B11 | A `✗` leaves the clock exactly as it was: no red mark on the face, no error sound, no shake, no change of screen. |
| B12 | Every prompt is spoken on arrival, guarded by an item key so a re-render does not re-speak it. A speaker button repeats on demand. |
| B13 | Volume persists across five steps (30–100%, default 85%); size defaults to the stylesheet `clamp()` and only changes when an adult presses the size buttons. |
| B14 | Best streak persists across sessions; the current streak resets per round. |
| B15 | Interactive targets are ≥96 px in their smallest dimension, and the ✓ / ✗ pair is widely separated. |

## 7. Language

**English default, Cantonese toggle.** The toggle is a header pill, persisted, and switches audio
and prompt text together; the clock face is unchanged.

- `en` — British English: "three o'clock", "half past two", "quarter to four", "twenty-five past
  four". Matches the UK ladder.
- `yue` — Cantonese. **The phrase table is a reviewed artefact, not generated text.** HK colloquial
  reading (`三點三` for 3:15, `三點九` for 3:45, from the `字` five-minute unit) differs from
  school/textbook forms (`三點十五分`, `三點四十五分`). 48 phrases (12 hours × 4 phases) go to a
  native speaker before any Cantonese audio is produced. Until then the locale is marked
  `yue: unreviewed` and the Cantonese criterion (AC-27) is **conditional**.

## 8. Storage

`localStorage`, one namespace `clock.v1.`:

| Key | Type | Meaning |
| --- | --- | --- |
| `clock.v1.profile` | `{ name?: string }` | optional name, locally typed |
| `clock.v1.level` | `string` | last level id |
| `clock.v1.locale` | `'en' \| 'yue'` | audio/prompt language |
| `clock.v1.volume` | `number` | 0.3–1.0, five steps |
| `clock.v1.size` | `number \| null` | `null` = stylesheet `clamp()`; else a multiplier 1.0–3.0 |
| `clock.v1.badges` | `string[]` | cleared level ids |
| `clock.v1.streak` | `{ best: number }` | best streak only |

No other persistence. Clearing site data resets everything; that must not break the app.

## 9. Audio

- Pre-generated, single voice per locale, committed to `public/audio/<locale>/`.
- English: `en-GB-SoniaNeural`, rate −8%, mono 22.05 kHz, −14 LUFS.
- Cantonese voice chosen once the phrase table is signed off (§7).
- Files: 48 English time phrases + ~12 prompts + short praise. Browser speech synthesis is a
  fallback only; a missing file must not fail the round.
- The manifest is generated from the level data, not hand-written, and rule 7 checks it.

## 10. Acceptance criteria

Single-purpose, `Given / When / Then`, stable numbering. *(new)* = added in v1.1; *(rev)* =
materially rewritten.

### Geometry

**AC-01** Given a clock showing 3:30, when the face renders, then the hour hand is at 105° (±0.01°)
and the minute hand at 180°.

**AC-02** Given 12:30, when the face renders, then the hour hand is at 15° — past the 12, not on it.

**AC-03** Given any time, when the face renders, then `hourAngle === (hour % 12) * 30 + minute * 0.5`
— never snapped to a numeral.

**AC-04** Given a level with `face.hands: 'hour'`, when a question renders, then no minute hand, no
minute marks and no minute labels exist in the DOM.

**AC-05** *(new)* Given any `:30` time on a two-hand face, when the face renders, then the hour hand
is strictly between two numerals — not within 2° of either.

### Content and model

**AC-06** *(rev)* Given the committed `src/levels.json`, when `npm run validate:levels` runs, then it
exits 0 — including for the eight non-clock levels.

**AC-07** Given a level file with any single violation of §4.5's eight rules, when the validator
runs, then it fails, naming the level id and the rule number.

**AC-08** *(rev)* Given level `t2.1` (`R×6, S×4`), when its round is built, then every `read` step
precedes every `set` step.

**AC-09** *(rev)* Given any round, when it is generated, then no time repeats within 2 positions of
itself.

**AC-10** *(new)* Given the 20 levels in `levels.json`, when the app renders each one, then every
level is renderable from its declared `content` and `face` alone — no level-id-specific branch in
the view layer.

**AC-11** *(new)* Given level `t3.1`, when a pair is presented, then exactly one face has its hour
hand on a numeral and the other has it strictly between two numerals.

**AC-12** *(new)* Given a `:30` face with the hour hand between 2 and 3, when the adult marks, then
"half past two" is recorded correct and "half past three" is recorded not yet.

### Flow and marking

**AC-13** Given a `read` item, when the child answers, then only `✓ Got it` and `✗ Not yet` are
offered, and the app evaluates nothing itself.

**AC-14** *(rev)* Given a `set` item, when both hands are within 3° of the target, then the app
records it correct and `Done` advances.

**AC-15** *(new)* Given a `set` item at `:30`, when the child drags the hour hand to any point
between the two numerals, then on release it snaps to the halfway angle.

**AC-16** *(rev)* Given a wrong answer at item 2 of a round, when the round continues, then that item
reappears no earlier than position 5.

**AC-17** Given a completed round, when the summary renders, then it shows ✓ of N, offers `Again`
and `Change level`, and shows no percentage or grade.

**AC-18** Given a `build` item with 10 of 12 numerals within 12° of ideal, when the child presses
`Done`, then the item is recorded correct.

**AC-19** *(new)* Given a `read` item marked `✗ Not yet`, when the verdict is recorded, then the
clock's geometry and styling are unchanged, no error sound plays, and the screen does not advance.

### Rewards

**AC-20** Given a round where the track completes, when the last item is marked, then the
celebration overlay appears.

**AC-21** Given a celebration dismissed in the previous round, when the next round's track
completes, then the celebration appears again.

**AC-22** *(rev)* Given a round of N items ending below `round(0.8 × N)` correct, then no badge is
awarded and the level is not marked cleared — tested at N=10 (7 correct) and N=4 (2 correct).

**AC-23** Given a round at or above the threshold on a previously uncleared level, when it ends,
then the badge id is added to `clock.v1.badges` and the setup shelf shows it filled.

**AC-24** Given two consecutive clears of a level, when the summary is dismissed, then the next
level is highlighted as *suggested*, and no level is locked.

**AC-25** *(new)* Given a fresh install, when the level picker opens, then all 20 levels are
selectable.

**AC-26** *(new)* Given a level with 6 items, when a round runs, then the progress track has 6 steps
and completes on the sixth correct answer.

### Language

**AC-27** *(rev, conditional on R1)* Given `clock.v1.locale === 'yue'` **and a reviewed Cantonese
phrase table**, when a round starts, then prompts and time phrases are spoken from the Cantonese
manifest and the prompt text is the Cantonese form. Not testable until R1 clears.

**AC-28** Given a time with no audio file in the active locale, when it is spoken, then the app
falls back without failing the round, and the child sees no error.

**AC-29** Given the locale toggle is pressed mid-session, when the next item appears, then the new
locale is used and the choice persists across reloads.

**AC-30** *(new)* Given an item keyed `t3.2:3:30`, when the view re-renders without the item
changing, then the prompt is not spoken again; when the speaker button is pressed, then it is.

### Storage, size and guardrails

**AC-31** Given a name typed at setup, when the app is reloaded, then the name is still shown, and a
search of the repo and the built `dist/` finds no occurrence of it.

**AC-32** Given cleared site data, when the app loads, then it opens at `t0.1` with no badges and no
error.

**AC-33** Given the built `dist/`, when `npm run guardrail:scan` runs, then it fails if any tracked
file contains an email address, a private IP address, a token, or one of the project's declared
banned child-data strings (that list lives in `scripts/guardrail-scan.mjs`, not in prose).

**AC-34** Given the app loaded once and then taken offline, when a full round is played, then it
completes — no runtime network calls.

**AC-35** *(new)* Given the play screen at default size, when targets are measured, then every
interactive element is ≥96 px in its smallest dimension.

**AC-36** *(new)* Given volume and size changed, when the app is reloaded, then both are restored;
given no size has ever been set, then the clock uses the stylesheet `clamp()` value.

## 12. Build order

1. **Geometry + level data + validator** — `clock.test.ts` red first, then green. No UI.
2. **Content payloads for T0/T1** — the eight non-clock levels renderable as data before any clock
   is drawn.
3. **Face renderer** (SVG) against the geometry, with a static harness page.
4. **Play screen for `choose` and `order`** — playable at T0/T1 with no clock at all.
5. **Play screen for `read` and `set`**, with the adult verdict pad and the `:30` snap.
6. **Rewards** — track (length from the round), celebration, badges, streak.
7. **Audio**, English, generated from the level data.
8. **Cantonese phrase table + audio**, after the native check (R1).
9. **`build` and `tap` tasks** (t1.1, t1.3, t1.4).
10. **Cloudflare Pages deploy** with the custom domain.

## 13. Deploy

**Cloudflare Pages directly** — no GitHub Pages step. POC for personal and family/friends use.
Static build, `base: './'`, no server. Custom domain `clock.zt489.com` per the existing DNS-01
pattern; the deploy follows the `cloudflare-pages-deploys` runbook (scoped API token, wrangler,
real-fetch verification — not a green dashboard).

## 14. Risks and open items

**R1 — The Cantonese phrase table is not a translation job** (§7). 48 phrases to a native speaker
before any Cantonese audio is generated. AC-27 stays conditional until then.

**R2 — Audio volume of work.** 48 English phrases ≈ 10 minutes of generation; the Cantonese set
doubles it and needs a voice choice.

**R3 — `build` tolerance.** 12° may be too tight for a four-year-old's fine motor control on a
tablet; if he cannot pass t1.4, widen to 15° and record which value landed.

**R4 — Whether he enjoys it** cannot be specified. First real feedback outranks this document.

**R5 — Round length vs "a set of ten".** Six levels are deliberately not 10 items (3, 4, 6, 8)
because their item is heavy — one face build is 12 placements. Every T2–T4 level *is* 10. If the
adult-facing model should always be ten, the alternative is to score sub-steps (a build counting
thirds), at the cost of a more complicated track. **Default: track length follows the round.**

**R6 — Day names are text.** t0.4 uses day tiles and t0.1 labelled cards; a four-year-old cannot
read them, which sits against §2's no-reading non-goal. Mitigation: pictorial tiles, day names
spoken when tapped, an adult who reads aloud. If he cannot use t0.4 unaided, that is expected.
